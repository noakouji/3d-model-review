# build123d でモデリングするときの作法

このビューアと組み合わせる前提の運用メモ。ライブラリのAPIリファレンスではない。
API は build123d 本体のドキュメント、MCPサーバーを使うなら `build123d://quickref` を見る。

---

## なぜコードで書くのか

AIエージェントにGUIのCADを操作させるアプローチは、**面の指し方**で破綻する。

GUI由来のAPIは面を `Face1` `Face7` のようなIDで指す。ところが寸法をひとつ変えると
IDは平気で付け替わる。「`Face3` を面取り」と書いたコードは、板厚を 5mm から 6mm に
変えた瞬間に別の面を面取りし始める。エージェントは間違えたことにすら気づけない。

コードで書くと、面を**条件で選べる**。

```python
# ✅ 意味で指す。寸法が変わっても指し先は変わらない
part.faces().sort_by(Axis.Z)[-1]          # Z座標が最大の面
part.faces().filter_by(Axis.Z)            # Z軸に垂直な面すべて
part.edges().filter_by(Axis.Z)            # Z方向の（＝縦の）エッジ

# ❌ 位置で指す。寸法を変えると壊れる
part.faces()[3]
```

これが build123d を選ぶ一番の理由。「Z座標が最大の面」は、板厚を変えても
**依然としてZ座標が最大の面**であり続ける。設計意図がコードに残る。

副次的な利点として、検証も同じPythonで書ける。体積を測る、干渉体積を出す、
バウンディングボックスを確認する——これが全部同じ言語で書けるので、
エージェントが **生成 → 数値検証 → レンダリング** のループを自分で回せる。

## 何が得意で、何が不得意か

| | 向いている | 向いていない |
|---|---|---|
| build123d | 平面・押し出し・回転体・穴・面取り・嵌合部品・治具・筐体 | 有機的な曲面、造形的なフォルム |
| Blender 等 | 有機曲面、キャラクター、意匠 | 寸法精度、パラメータ変更 |

**寸法が命のものは build123d、形が命のものは別ツール。** 無理に一本化しない。
画像から3Dを起こすAI（Tripo / Meshy 等）は機構部品の嵌合精度が出ないので、
はめあいのある部品には使わない。

## 進め方

### 1. 作る前にスペックを確定させる

読みながら作らない。まず**名前付きパラメータのブロック**に落とす。

```python
# すべて mm。実測は 2026-08-16 にノギスで測定
PLATE_W, PLATE_D, PLATE_T = 80.0, 50.0, 5.0
BOLT_DIA   = 6.6      # M6 バカ穴
BOLT_INSET = 8.0      # 各辺から穴中心まで
CLEARANCE  = 0.3      # はめあいのすきま（ここ1箇所で全体を制御する）
```

**マジックナンバーを式の中に直接書かない。** 「穴の位置を1mmずらして」と言われたときに
1箇所直せば済む状態にしておく。あとで注釈が飛んでくる前提の設計にする。

公差は `CLEARANCE` のような**1変数に集約**する。プリンタや材料が変われば
ここだけ振り直せばいい状態にしておく。

### 2. 1フィーチャーずつ組んで、都度測る

60行を一気に流して失敗すると、どこで壊れたのかわからない。
1つのフィーチャー（または1つのブーリアン）ごとに実行して、**そのつど測る**。

MCPサーバーを使う場合:

```
execute()      # 1フィーチャー追加
measure()      # 体積・バウンディングボックス・面数を確認
render_view()  # 数値がおかしくなければ絵を見る
```

**順番が重要。見る前に測る。** レンダリング画像は「それらしく見える」ことがある。
体積がゼロなら、どんなに綺麗な絵が出ても中身は空。

ブーリアン（`-` や `+`）の直後は必ず測る。減算しすぎてソリッドが分裂している、
あるいは何も削れていない、はここで捕まる。

### 3. 数値で検証する

見た目でなく数字で確かめられるものは、全部数字で確かめる。

- **体積** — 減算前後の差分が、削ったはずの体積と一致するか
- **バウンディングボックス** — 外形が仕様どおりか。想定より大きければどこかがはみ出している
- **干渉体積** — 組んだ状態で2つのソリッドの共通部分を取る。**0でなければ組めない**
- **面数** — フィレット後に想定より面が増減していたら、意図しないエッジに掛かっている

嵌合部品は、相手部品もモデル化して**組立状態で干渉チェックする**。
片方だけ見ていても、はまるかどうかはわからない。

### 4. ビューアに出してレビューしてもらう

STL を書き出してビューアを起動する（[SKILL.md](../SKILL.md) の手順）。
ここで初めて人間の目に入る。

**バージョンを分けて出す。** 上書きすると比較ができない。

### 5. 注釈が返ってきたら、直して 2 に戻る

注釈の `coords` はモデル座標系そのまま。パラメータブロックのどの値が効いているかを
特定して、**その値を変える**。形状式を直接いじり始めたら設計が壊れている合図。

## はめあいは刷るまでわからない

干渉体積が0でも、実際にはまるかどうかは別問題。
プリンタの収縮・積層方向・フィラメントで実寸は変わる。

**本体を刷る前に、小さなテストピースを刷る。** はめあい部だけを切り出した
数分で刷れるピースを、`CLEARANCE` を 0.1 刻みで数個並べて出力する。
本体を2時間かけて刷ってから入らないことに気づくより、はるかに速い。

刷って確定した `CLEARANCE` は、そのプリンタ・材料の値としてメモに残す。

## 地雷はファイルに貯める

同じ失敗を繰り返さないために、踏んだ地雷を `docs/pitfalls.md` のような
1ファイルに書き足していく。そして **CLAUDE.md に「作業前に読む」と書く。**
これをやるかやらないかで、2回目以降の速度がまるで変わる。

書くのは「何をしたら」「何が起きて」「どう回避したか」の3点だけでいい。

### 最初から書いておくと得なもの

**円柱のエッジにフィレットは掛からない。**
OCCT ベースのカーネル共通の挙動で、円柱側面には直線エッジが無いため
`Standard_Failure` になる。上面のエッジに**チャンファー**を掛ける。

```python
# ❌ 例外になる
part = fillet(cylinder.edges().filter_by(Axis.Z), radius=2)

# ✅ 上面の円形エッジに面取り
part = chamfer(cylinder.faces().sort_by(Axis.Z)[-1].edges(), length=1)
```

**フィレット半径は隣接する形状より小さくする。**
板厚 5mm に R3 のフィレットを両面から掛けると破綻する。
失敗したら半径を落とす前に、**そもそも掛かる余地があるか**を計算する。

**フィレットは最後に掛ける。**
フィレット後にブーリアンをすると、丸めた面を切ってしまって形が破綻しやすい。
穴あけ・切り欠きを全部終えてから丸める。

**メッシュ破損は STL 書き出し時ではなく、その前のブーリアンで起きている。**
STL がおかしいときは書き出し設定を疑う前に、直前のブーリアン後の
体積・面数を確認する。

## セットアップ

MCPサーバー経由が最も楽（永続セッションが保たれるので、1フィーチャーずつの
実行と測定がそのまま成立する）。素の Python で使う場合は:

```bash
python3 -m venv .venv
.venv/bin/pip install build123d
```

build123d は OCCT を含むため初回インストールは重い。プロジェクトごとに venv を切って
グローバル環境を汚さないほうがいい。
